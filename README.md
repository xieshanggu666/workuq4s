# 末日地堡生存

一款基于 **FastAPI + SQLite** 后端与 **Vue 3（本地运行时，离线可用）** 前端的末日地堡模拟经营游戏。

## 游戏说明

地表已覆灭，你带领一批幸存者藏身地堡。你需要管理**有限的食物、水源、电力、氧气**，安置与分配**居民岗位**，扩建**基础设施**，并在每天的**危机轮盘**中做出抉择，坚持到第 120 天迎来曙光。

## 核心机制

- **资源守恒循环**：每日净变化 = 设施产出 − 人口消耗。产出受设施等级、相关岗位（农民/工程师）与平均士气加成影响。
- **四类资源**：食物 / 水源 / 电力 / 氧气，任一枯竭都会引发减员。
- **居民管理**：每位幸存者有健康与士气，健康低于阈值士气下滑；士气影响整体产出效率。可为居民指派岗位（工程师 / 农民 / 医护 / 杂工）。
- **设施扩建**：穹顶菜园（产食物）、净水器（产水）、发电机（产电）、水培制氧（产氧）、医疗舱（被动回血）、医疗救治中心（病例收治）、仓储区。可建造与升级（等级加成 x1.6）。
- **医疗救治中心**：受伤或染疫居民经历 **登记 → 治疗/隔离 → 康复/病亡** 的完整病例链。每级中心提供 2 张救治床位，每名当值「医护」再加 1 床并提升救治效率；治疗/隔离按床每日消耗食物、水源与电力，物资不足当日停诊。登记未收治病例会持续恶化，未隔离的传染病例可能在堡内扩散（医护越多传播概率越低），隔离即切断传播。疫病危机、探索/押运途中受伤会在结算后自动建档；在治病例暂停生产，有未结病例者不得离堡，离堡成员的病例随队伍冻结、回堡后续治。活跃病例每日抬高地堡**医疗危机**表（登记未收治 +4/床日、在治 +2/床日），越过高压阈值（70）后在堡全员士气持续受挫。终局按登记/康复/病亡/累计救治床日做危机后健康结算。
- **地堡联盟援助协议**：在「联盟援助」页查看联盟公告板上的医疗援助请求，由**管理者发起、医护负责人会签、外部聚落签约**共同完成签约：托管医援物资冻结、组建 1-3 人援助押运队；推进后外部聚落按地堡信誉（+会签医护资质）掷签约，通过即离堡押运（与探索队同口径：暂停生产、不耗地堡口粮、不参与地堡危机），在途可能遭遇疫区流民/检疫暴露/辐射尘暴/车辆故障等事件；抵达日先过**押运审核（疫区检疫关卡，信誉 + 随队医护决定通关率）**，通关才**交付**。成功交付：联盟回礼入库、全员获得医疗救治（活跃病例可当场康复）、医疗危机 −35、信誉 +8、士气上升；押运审核未过：托管退回、危机 +10、信誉 −6；途中弃货/全损/全员失联或会签医护失格（逾期）则协议失败/关闭：剩余货物回退、危机 +25 且疫情反扑（在堡最虚弱者立为疫病例）、信誉重罚 −10。proposed 阶段可随时撤约全额退还；签约/押运/终局口径与贸易订单一致，终局强制安全收敛，不留僵尸协议。
- **跨聚落难民安置**：在「难民安置」页查看外部聚落每日轮换的安置申请（每份 1-3 人，带健康/士气/疫区接触史/擅长岗位）。地堡**审核拒绝**（信誉 −2）或**批准**：批准后难民进入堡内**隔离检疫**（2 天），隔离舱按人每日消耗食物、水源与电力，物资不足当日断供、在检难民健康与士气下滑；检疫中每日医疗筛查——接触史者按基础概率（医护越多越低）确诊并损血，已确诊者在救治中心 + 当值医护下接受救治、健康跨过 75 即转阴，无救治体系则每日恶化，健康归零即检疫病亡（不计入居民人口、每人信誉 −2）；检疫期满无人存活则安置失败关闭。有幸存者时进入**待接纳**（暂停消耗）：**接纳并逐人分配岗位**（缺省按擅长岗位）后转为正式居民，每人信誉 +4、在堡全员士气 +5；接纳瞬间联动医疗病例——未转阴的疫病例立即占用救治床位转入**隔离**（床位不足则登记待收治、持续抬升医疗危机），健康低于 35 的体弱者登记普通伤病病例，健康者不建档；也可**全部遣返**（信誉 −5、全员士气 −3）。安置在堡内完成、不派离堡队伍，与探索队/贸易/援助可同时进行；审核/接纳/遣返均有档案级幂等凭据，连点与并发落败安全回放，终局随档案清空、累计安置统计写入结局。
- **危机轮盘**：每天约 45% 概率触发危机事件，均可多选决策（辐射风暴、内讧、氧气泄漏、疫病、盗匪、物资舱、暴雪、路过商队），不同选择带来不同的资源 / 健康 / 士气 / 信誉后果。
- **贸易救援**：在「贸易救援」页联络外部聚落，市场每日轮换四条报价（紧急求援 / 对外采购）。订单走 **申请 → 审核 → 押运运输 → 交付 / 失败回退** 状态链：申请时冻结托管物资，外部聚落按地堡信誉掷审核；通过后押运队离堡（与探索队同口径：暂停生产、不耗地堡口粮、不参与地堡危机），在途可能触发途中事件（截道 / 沙暴 / 盘查 / 故障），途中货损按残存比例结算；成功则回礼/采购入库并提升信誉与士气，失败（交易黄了 / 弃货 / 全损 / 全员失联）则剩余货物退回、扣信誉。终局日订单强制安全收敛，不留僵尸订单。
- **结局结算**：存活至第 120 天**胜利**；人口归零或四资源全线枯竭则**失败**。胜局 / 败局均按幸存者 × 天数 × 士气系数结算评分。

## 快速开始

环境要求：**Node.js**（任意近年版本，仅用于命令调度，前端无需构建）与 **Python 3.10+**。
前端静态资源由 FastAPI 后端同端口托管，因此一条命令即可启动前后端：

```bash
npm run setup   # 安装 Python 依赖并初始化数据库（仅需一次）
npm start       # 一键启动前后端
```

访问 http://127.0.0.1:8000 ，在档案大厅新建或继续一局游戏。

| 命令 | 作用 |
|---|---|
| `npm run setup` | 安装 Python 依赖 + 初始化数据库（幂等，含演示档案） |
| `npm start` | 生产模式启动（`PORT=8080 npm start` 可换端口，`HOST`/`PYTHON` 同理） |
| `npm run dev` | 开发模式启动（代码变更自动重载） |
| `npm run init-db` | 仅初始化/补齐数据库 |
| `npm test` | 运行 pytest 测试套件（`npm test -- -k xxx` 可透传参数） |

## 状态流转与一致性约定

档案状态机只有四个阶段，所有后端守卫以前端禁用为辅助、以后端校验为准：

| 阶段 | 含义 | 允许的动作 |
|---|---|---|
| `daily` | 每日阶段 | 建造/升级/调岗/登记收治病例/派遣探索队/申请贸易或联盟援助/审核难民安置/推进一天 |
| `crisis` | 地堡危机待处理 | 仅结算当前危机 |
| `expedition` | 探索遭遇待处理 | 仅结算当前遭遇 |
| `trade` | 押运途中事件待处理 | 仅结算当前途中事件 |
| `aid` | 联盟援助途中事件待处理 | 仅结算当前援助途中事件 |
| `ended` | 胜利/失败终局 | 只读，拒绝一切变更 |

- **待决事件统一管线**：每日危机、探索遭遇、贸易押运途中事件、联盟援助途中事件四类挂起抉择共用同一套机制（`engine.py` 的 `_PENDING_SLOTS` 槽位注册表）——同构快照（token/事件/目标/选项）随档案落库、刷新后恢复同一场抉择；档案级幂等凭据（`last_resolution` / `last_expedition` / `last_trade` / `last_aid`）支持连点与并发落败安全回放；同一互斥状态机（任一抉择挂起即锁定经营与推进）；终局一次性清空全部槽位。存储位置保持原样（`pending_crisis` 列、`expedition.pending_encounter`、`trade_order.pending_incident`、`aid_pact.pending_incident`），旧存档无需迁移即可加载。
- **每日推进**：`daily → 产出消耗/健康士气 → (行军+遭遇? | 危机? | 终局)`。抉择不可被“再点一天”跳过。
- **探索队**：离堡人员暂停地堡生产、不消耗地堡口粮、不参与地堡危机效果；行军消耗自带口粮，遭遇替代当日地堡危机，返程统一结算战利品/余粮/伤亡。终局日队伍仍在外时先安全返程再收敛到 `ended`，不留“僵尸队伍”。
- **贸易救援**：订单与探索队/援助协议互斥（同一时间只允许一支在外队伍/一笔在谈订单或协议）。审核中（`reviewing`）押运队仍在堡正常生产，可随时撤单且托管全额退还；审核通过进入在途（`transporting`）后不可撤单。押运队在途口径与探索队完全一致（暂停生产/口粮、跳过地堡危机与医疗舱）。途中事件挂起进入 `trade` 阶段并替代当日地堡危机；弃货/全损/全员失联在事件结算时当场收敛为失败回退，抵达日再掷一次交付（成功率随信誉）。失败回退按残存比例退还托管（求援未送达/采购货损），成功入库同样遵循"终局裁决先快照"——全线枯竭当日的回礼不会复活败局。
- **联盟援助**：协议状态链 `proposed`（三方签约待外部确认，可随时撤约退款；会签医护失去资质则逾期关闭全额退款）→ `escorting`（押运在途，途中事件挂起进入 `aid` 阶段）→ 抵达日先过押运审核（检疫关卡）→ `delivered`（通关交付）/ `failed`（押运审核未过/弃货/全损/失联）。外部签约率随信誉并受会签医护资质加成，检疫通关率随信誉并受随队医护加成。交付回写**信誉（+8）、资源（联盟回礼入库）、医疗危机（−35）与全员救治**；失败回写信誉（−6/−10）、托管退回与医疗危机反扑（+10/+25、可能新增疫病例）。离堡口径、幂等回放与终局安全收敛与贸易订单完全一致。
- **难民安置**：难民在堡内隔离舱安置，**不派离堡队伍、不与探索队/贸易/援助互斥**，但同样受待决事件状态机约束（任一抉择挂起时审核/接纳/遣返一律锁定）。状态链为公告板申请（确定性按日轮换）→ `quarantine`（隔离检疫，每日推进时在基地生产消耗/医疗结算之后结算隔离配给与筛查）→ `admitting`（检疫期满待接纳，暂停一切消耗）→ 接纳（转为正式居民并写病例）/ `repatriated`（遣返）/ `failed`（检疫病亡清零）/ `rejected`（拒绝）。检疫中的难民**不是居民**：不计人口、不耗基地口粮、不向医疗危机施压；接纳瞬间才加入居民表并联动病例簿（疫病例优先占隔离床，不足转登记待收治），其在治/待收治压力自次日医疗结算起累积。审核/接纳/遣返各有档案级幂等凭据（`last_refugee`，审核绑定 `application_id`、接纳/遣返绑定安置 `token`），连点与并发落败（含接纳↔遣返互相落败）均安全回放；终局日在检/待接纳安置随 `_finish` 一次性清空，累计统计（申请/批准/接纳/拒绝/遣返/病亡）写入 `outcome.refugee`。
- **并发**：`row_version` 乐观锁保证每日推进/危机/遭遇/途中事件只落一次；落败方凭一次性 `token` 与档案级幂等凭据（`last_resolution` / `last_expedition` / `last_trade` / `last_aid` / `last_refugee`）安全回放，过期或串档请求返回 409。
- **旧存档**：启动时自动补列（`pending_crisis` / `last_resolution` / `expedition` / `last_expedition` / `trade_order` / `last_trade` / `aid_pact` / `last_aid` / `refugee_intake` / `last_refugee` / `refugee_stats` / `medical_cases` / `medical_crisis` / `reputation` / `row_version`），并归一化损坏/悬空快照（已结束档案清除悬而未决状态、失踪成员/目标剔除、悬空/重复或绑定死者的病例收敛、援助协议悬空成员/会签人剔除、难民安置结构残缺或已无存活者时清除、`survivors` 与居民表对齐），归一化本身幂等。
